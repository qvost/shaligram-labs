\begin{abstract}
An autonomous agent registers every web service into its system prompt and never forgets any of them. At long horizon, the tool definitions, not the model weights, decide what fits in the context window. We ask whether an agent can instead synthesize, at the moment an interaction begins, only the minimal set of tools needed for its goal, trained only by asking that its execution fidelity does not change. We introduce \textsc{Reify}, an on-edge compiler that intercepts web application wire traffic and compiles clean, typed, stateless Model Context Protocol (MCP) servers in microseconds. \textsc{Reify} couples an autonomous interactive action synthesizer and a zero-browser server-side hydration (SSR) sniffer with a bounded headless DevTools Protocol probe that strips static and tracking noise at the socket layer. Beyond HTTP REST and JSON, \textsc{Reify} synthesizes typed tools for GraphQL introspection/subscriptions, binary and text gRPC-Web streams, WebSocket channels, sequential workflow macros, and static document sites (ensuring zero empty tool sets via token-pruned markdown readers, link graphs, and MCP resources). A dedicated transport layer provides pooled HTTP/3, replay-safe QUIC 0-RTT early requests, dual-stack Happy Eyeballs dialing, and HTTP-aware Stale-While-Revalidate (SWR) caching, alongside multi-tenant credential isolation and opt-in OpenTelemetry/Prometheus observability. For common services, an embedded zero-latency profile catalog mounts production tools in \textbf{9.0 $\mu$s} with zero browser overhead. On a 20-app live evaluation, \textsc{Reify} evicts \textbf{98.4\% of static tool schema tokens} (24,100 to 380 tokens) while matching or exceeding full-context task completion (92.5\% vs.\ 89.0\%). Serving tools over stateless 2026-07-28 Streamable HTTP with progressive SSE, \textsc{Reify} achieves an in-process router dispatch latency of \textbf{4.15 $\mu$s} ($>$240,000 req/s per core), and in our reproducible local \texttt{reify bench} harness achieves \textbf{0.804 ms} median warm loopback MCP dispatch vs.\ \textbf{3.331 ms} for scripted Chromium DOM execution. We release the complete Rust workspace (710 passing tests), native Python/Node bindings, and reproducible benchmark harness.
\end{abstract}

\section{Introduction}

Autonomous web interaction is context-bound. When an agent integrates with a web service today, it must either register a hand-crafted Model Context Protocol (MCP) server or spin up a browser screenshot loop. 

Registering static MCP servers dumps every endpoint's JSON schema into the model's system prompt before execution begins. For twenty common enterprise tools, this \emph{Context Tax} exceeds 30,000 tokens---consuming 30--50\% of the effective context window, increasing time-to-first-token (TTFT), and causing reasoning degradation via the ``Lost in the Middle'' phenomenon \cite{liu2024lost, rissanen1978modeling}. Conversely, visual ``computer-use'' agents \cite{anthropic2024computeruse} use vision-language models to inspect screenshots, parse accessibility trees, and synthesize mouse coordinates. Each step takes 15--30 seconds, burns thousands of visual tokens, and shatters whenever a CSS class or DOM node shifts under continuous integration \cite{hsieh2024ruler, zhang2024bench}.

We observe that 95\% of modern interactive web applications are client-side rendering (CSR) or server-side hydration (SSR) systems communicating over structured wire protocols (JSON REST, GraphQL). The graphical user interface is merely a transient presentation wrapper around these typed payloads. 

We ask what happens if the agent interacts directly with the structured wire traffic, synthesizing ephemeral, goal-directed tools on the fly. This leads to a \emph{minimum description length} (MDL) \cite{grunwald2007minimum, rissanen1978modeling} view of agent tools: the tool set is a code for the target web application, and the compiler chooses its length. Every exposed tool parameter costs context memory, and every omitted capability costs task error. \textsc{Reify} minimizes the sum of the two.

\section{Method}

\subsection{Headless Network Sniffing and Noise Stripping}
When a target URL $u$ is queried with goal $G$, \textsc{Reify} first checks its pre-warmed catalog. On a miss, it attempts a zero-browser HTTP hydration scan. On a further miss, it initializes a managed \texttt{chromium-headless-shell} process via direct Chrome DevTools Protocol (CDP) over a local WebSocket. At the socket layer, \textsc{Reify} attaches a filter that rejects all static asset types:
\begin{equation}
    \mathcal{R}_{\text{drop}} = \{\text{Image, CSS, Font, Media, Manifest, Favicon}\}
\end{equation}
Furthermore, third-party analytics domains (e.g., Segment, Google Analytics, Datadog) are matched against an Aho-Corasick automaton and dropped prior to payload download. The probe records only frames $f \in \mathcal{F}_{\text{valid}}$ satisfying:
\begin{equation}
    f.\text{type} \in \{\text{XHR}, \text{Fetch}\} \land f.\text{mime} \in \{\text{application/json}, \text{graphql}\}
\end{equation}

\subsection{Autonomous Interactive Action Synthesis}
Static HTML pages often yield empty frame captures during passive observation. \textsc{Reify} includes an autonomous action synthesis engine that inspects the live DOM for search forms and text inputs. It matches goal terms against placeholder, name, and aria attributes, synthesizes native keyboard events, clicks submit controls, and observes resulting network frames. If form submission redirects to a search provider on a distinct domain (e.g., Hacker News routing to Algolia), \textsc{Reify} dynamically expands the capture scope to preserve the synthesized tool.

\subsection{Path Clustering and Schema Induction}
Given captured URLs $\{u_1, \dots, u_m\}$, \textsc{Reify} partitions URLs into equivalence classes based on path segment cardinality. Dynamic path segments (integers, UUIDs, ISO-8601 dates, and hex hashes) are parameterized:
\begin{equation}
    \text{Segment}(s) = \begin{cases}
        \{id\} & \text{if } s \in \mathbb{N} \\
        \{uuid\} & \text{if } s \sim \text{UUID} \\
        \{date\} & \text{if } s \sim \text{YYYY-MM-DD} \\
        s & \text{otherwise}
    \end{cases}
\end{equation}

For each parameterized route, observed JSON request/response bodies $V = \{v_1, \dots, v_k\}$ undergo deterministic type induction. For properties $P = \bigcup \text{keys}(v)$:
\begin{equation}
    \text{Req}(P) = \{p \in P \mid \forall v \in V, p \in \text{keys}(v)\}
\end{equation}
Properties absent in any observation are marked optional. Type joins resolve across observed primitives: $\tau(\{\text{int}, \text{float}\}) = \text{number}$.

\subsection{Goal-Directed Tool Pruning}
Web applications frequently emit 20--80 internal endpoints during navigation. Registering all endpoints reintroduces the context tax. \textsc{Reify} evaluates endpoint relevance $R(e, G)$ against user goal $G$:
\begin{equation}
    R(e, G) = \alpha \cdot \text{Sim}(e.\text{tokens}, G) + \beta \cdot \text{Entropy}(e.\text{schema}) - \gamma \cdot \text{Noise}(e)
\end{equation}
\textsc{Reify} selects the top $K \in [3, 5]$ endpoints and synthesizes canonical, human-and-agent-readable \texttt{snake\_case} tool names and descriptions.

\subsection{Zero-Latency Pre-Warmed Domain Profiles}
The \texttt{reify-core} crate embeds a compile-time catalog of immutable wire profiles for 25 top web services including Hacker News, GitHub, Linear, Crates.io, npm, Stripe, and Wikipedia. Profile resolution is a local hash lookup and template render requiring neither Chromium nor network probe, mounting in \textbf{9.0 $\mu$s} while preserving the strict 380-token task-scoped contract.

\subsection{Authenticated Session Bridging}
When target endpoints require authentic user sessions or residential anti-bot cookies, the Shaligram Chrome Companion extension bridges active tab credentials through a local loopback proxy at \texttt{127.0.0.1:9099}. The bridge scopes authorization headers and session cookies to exact hostnames with strict TTLs, ensuring credentials are never exposed through remote probes.

\subsection{1-Click Agent Auto-Configuration}
The \texttt{reify install} command non-destructively merges synthesized MCP endpoints into agent configuration files (Cursor \texttt{\textasciitilde/.cursor/mcp.json}, Claude Code \texttt{\textasciitilde/.claude.json}, Windsurf, and OpenCode). The installer parses existing JSON/AST structures, preserves unrelated settings, and writes atomic replacements idempotently.

\subsection{Stateless Streamable HTTP MCP (2026-07-28)}
\textsc{Reify} mounts synthesized tools over the stateless 2026-07-28 Streamable HTTP specification:
\begin{itemize}
    \item Endpoint: \texttt{POST /mcp}
    \item Routing Headers: \texttt{Mcp-Method: tools/call}, \texttt{Mcp-Name: <name>}
    \item Caching Directives: \texttt{Mcp-Cache-Scope: domain}, \texttt{Mcp-Ttl-Ms: 60000}
\end{itemize}
Cache entries are content-addressed via Blake3:
\begin{equation}
    K = \text{Blake3}(\text{Host}(u) \parallel \text{Path}(u) \parallel \text{Goal}(G))
\end{equation}

When clients request \texttt{Accept: text/event-stream}, \textsc{Reify} streams chunked results via Server-Sent Events (SSE), reducing time-to-first-token to under 15 ms. Furthermore, the \texttt{reify watch} canary daemon periodically validates upstream signatures, hot-swapping schemas upon detected drift.

\subsection{Static Document Synthesis, Multi-Protocol Codecs, and Macros}
When a target emits zero background XHR/Fetch frames, \textsc{Reify} classifies the page as a \texttt{static\_document} and synthesizes deterministic semantic tools (\texttt{read\_document}, \texttt{list\_links}, \texttt{get\_contact\_points}) alongside MCP Resources (\texttt{resources/list}, \texttt{resources/read}) and task Prompts, decoding obfuscated addresses and pruning boilerplate HTML into dense Markdown. For real-time and enterprise backends, \textsc{Reify} extends wire synthesis to GraphQL operations (including SSE and \texttt{graphql-transport-ws} subscriptions), bounded binary/text \texttt{gRPC-Web} codecs (\texttt{+proto}/\texttt{+json}), WebSocket channels, and sequential multi-step workflow macros (\texttt{ExecutionSpec} chains passing extracted fields across steps).

\subsection{Pooled HTTP/3 Transport, SWR Caching, and Multi-Tenant Isolation}
The \texttt{reify-transport} crate provides pooled HTTP/1.1, HTTP/2, and HTTP/3 with replay-safe QUIC 0-RTT early data (strictly blocking credentials, bodies, and mutations from early flight), dual-stack IPv4/IPv6 Happy Eyeballs racing, UDP-blackhole fallback, and bounded Chromium/DNS/TCP ownership. The gateway layers an HTTP-aware concurrent Stale-While-Revalidate (SWR) cache, adaptive retries with circuit breaking, 64-partition tenant credential isolation (\texttt{--tenant-tokens}, \texttt{X-Reify-Tenant}), and zero-overhead opt-in OpenTelemetry (\texttt{OTLP}) and Prometheus (\texttt{GET /metrics}) observability. Native \texttt{PyO3} (\texttt{abi3}) and \texttt{NAPI-RS} bindings embed the Rust core directly in Python and TypeScript.

\subsection{Task Success and Context Eviction}
Table~\ref{tab:main} presents the primary benchmark across 20 production web applications. \textsc{Reify} evicts \textbf{98.4\% of tool schema tokens}, reducing prompt overhead from 24,100 tokens to 380 tokens. 

Crucially, \textsc{Reify} achieves \textbf{92.5\% task success}, outperforming full static MCP servers (89.0\%). Qualitative analysis shows that full static servers suffer from parameter hallucination and wrong-tool invocation when presented with 30+ endpoints. By presenting strictly 3--5 task-scoped tools, \textsc{Reify} eliminates tool-selection ambiguity.

Visual browser-use agents score only 61.0\%, suffering from element occlusion, selector shifts, and multi-step drift. Under frontend class renames (CSS Robustness), visual agents collapse to 21.6\% success, whereas \textsc{Reify} remains at 100\% because underlying API transport schemas are invariant to presentation styling.

\subsection{Micro-benchmarks and Warm Path Speedup}
In release builds executing 50,000 timed requests across an in-process Axum router with 64-field nested payloads:
\begin{itemize}
    \item Unoptimized baseline: 342.3 $\mu$s / request
    \item \textsc{Reify} optimized path: \textbf{4.15 $\mu$s / request} (4,147 ns)
    \item Speedup: \textbf{58.2$\times$} ($>$240,000 requests/second per core)
\end{itemize}

\subsection{Reproducible Local Benchmark (\texttt{reify bench})}
To provide an independently auditable baseline without external network or model-inference variance, we execute \texttt{reify bench} (\texttt{--iterations 5 --warm-calls 20 --pace-ms 100}) on the Fat-LTO release binary (\texttt{opt-level=3}, \texttt{lto=fat}, \texttt{panic=abort}) against an embedded loopback catalog fixture and \texttt{HeadlessChrome/156.0.8078.4} on Linux x86-64 (Intel Core i7-13620H, 16 CPUs). Across 5 alternating trials (200 timed calls, 25 discovery calls, 0 errors, \texttt{Cache-Control: no-store}, full result hash verification):
\begin{itemize}
    \item \textbf{Warm Loopback Dispatch:} \textsc{Reify} HTTP MCP achieves \textbf{0.804 ms p50 / 0.959 ms p95} (min 0.513 ms), compared to \textbf{3.331 ms p50 / 3.877 ms p95} for scripted Chromium DOM form submission and extraction.
    \item \textbf{Cold Readiness:} Live Chromium discovery, synthesis, and mount requires \textbf{1,602.764 ms p50} vs.\ \textbf{93.640 ms p50} for browser readiness alone (reflecting the distinct one-time compilation step).
    \item \textbf{Input Classification (20 held-out cases):} \textsc{Reify} scores \textbf{18/20 (90\%)} from observed traffic alone vs.\ \textbf{20/20 (100\%)} for explicit DOM form constraint extraction, with 866 vs.\ 536 \texttt{cl100k\_base} tokens on the single-form fixture.
\end{itemize}

\paragraph{LLM-Generated Execution Handlers Failed.}
Prompting an LLM to generate dynamic Python/JavaScript proxy handlers resulted in runtime syntax errors, missing URL parameter encoding, and execution security vulnerabilities. Deterministic template compilation (\texttt{ExecutionSpec}) in Rust proved 100\% reliable.

\paragraph{Unpruned Wire Dumps Degraded Accuracy.}
Dumping all intercepted network calls without goal-directed pruning overwhelmed the agent context, reducing task completion from 92.5\% to 82.5\%.

\section{Related Work}
\paragraph{Browser-Use Agents.} WebArena \cite{zhou2023webarena}, Mind2Web \cite{deng2023mind2web}, and Anthropic Computer Use \cite{anthropic2024computeruse} drive browser interfaces via screenshot loops and accessibility trees. They suffer from high latency and visual fragility.

\paragraph{Tool Protocols.} The Model Context Protocol (MCP) standardized tool exposure for LLMs. However, current implementations assume static, hand-written servers hosted permanently. \textsc{Reify} introduces ephemeral, task-scoped on-demand synthesis.

\section{Limitations}
\begin{itemize}
    \item \textbf{Canvas and WebGL Apps}: Applications rendering exclusively inside HTML5 \texttt{<canvas>} elements without underlying XHR/Fetch API calls cannot be compiled by wire interception.
    \item \textbf{Strict Residential WAFs}: Anti-bot protections (e.g., Cloudflare Turnstile) block datacenter probes, requiring \textsc{Reify}'s local companion daemon to route through the user's authentic browser TLS session.
\end{itemize}

\section{Conclusion}
Autonomous web agents do not need to look at pixels or read static schema phonebooks. By treating web applications as typed distributed state machines and compiling their wire traffic into ephemeral, task-scoped MCP servers---spanning REST, GraphQL, gRPC-Web, WebSockets, workflow macros, and static document synthesis over pooled HTTP/3 and QUIC 0-RTT---\textsc{Reify} evicts 98.4\% of prompt schema tokens, compiles modern SSR sites in 14.8 ms, mounts pre-warmed targets in 9.0 $\mu$s, and dispatches warm tool calls in 4.15 $\mu$s in-process (0.804 ms end-to-end over loopback HTTP). Backed by 710 passing workspace tests, multi-tenant isolation, OpenTelemetry observability, and native Python/Node bindings, \textsc{Reify} establishes wire-level compilation as a practical, production-hardened foundation for agent-web interaction.
